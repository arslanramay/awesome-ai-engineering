# Contributing

Thanks for wanting to add something. This list stays useful by staying small, so a few rules.

## What belongs here

- A **public** GitHub repository that is actively maintained.
- Something you'd use to build or ship an AI application: agents, MCP, RAG, model serving, evals, backend APIs or AWS deployment.
- A project with a real licence file. Say which licence it is.
- Projects that need a hosted service or have restrictive terms are fine. Just say so in the entry.

## What doesn't

- Archived repositories.
- Tutorials, courses and blog posts. Those belong in a different list.
- Projects you maintain that have no users yet. Come back when they do.
- Duplicates. If an existing entry already does the job, explain what yours does better.

## How to add an entry

1. Fork the repository and edit `README.md`.
2. Put the entry in the section it fits best, in the same format as its neighbours:

   ```markdown
   - [Project name](https://github.com/owner/repo) — One honest sentence on when to pick it. MIT.
   ```

3. Write the sentence in your own words. Don't paste the repository's tagline.
4. Check the link opens and the licence matches what GitHub shows.
5. Open one pull request per project, with a short note on why it deserves a spot.

## Style

- Plain language, no hype words like "revolutionary" or "blazing fast".
- Keep the sentence to one line where you can.
- End with the licence, or "Licence: see repository" if GitHub can't detect it.

## Removing entries

If a project is archived, abandoned or changes to a licence that no longer fits, open an issue or a pull request to remove it.
